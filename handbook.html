01 Getting in Everyone

The label press runs in a browser. There is nothing to install, and it works the same on the office PC and on a tablet on the line.

  1. Go to allcompanylabels.meatplus.ph.
  2. Sign in with your work email and password.
  3. If you have never used it, choose Create one, fill in your name, your @meatplus.ph email and a password.

“Waiting for approval”

A new account can sign in but sees nothing until an administrator gives it a role. This is normal. Ask an administrator to set you up on the Users tab — it takes them about ten seconds.

Leaving the station

Lock (top right) puts the sign-in screen back up but keeps everything where it is — use it when you step away from a shared machine. Sign out ends the session properly. Every label you print is recorded under your name, so do not let someone else print under yours.

02 Printing a label Everyone

This is the job. Everything else in the handbook exists to make this step correct.

  1. Choose the customer. This narrows the product list to that customer's items, loads that customer's label size, and is recorded in the print log. Customer details never appear on the label itself.
  2. Choose the product. Each entry reads Name · Pack size · Barcode number, so you can tell two similar products apart before you pick. Choosing one fills in all three fields below. Pick Custom entry to type a one-off label instead.
  3. Check the dates. Today sets the production date. The shelf-life buttons — +3 mo, +6 mo, +1 yr, +2 yr — set the expiry from it. You can always type a date instead.
  4. Enter the batch or lot if the box is showing. It only appears for code types that can carry one, and it goes inside the barcode rather than being printed as text.
  5. Set the number of copies.
  6. Look at the preview and the message underneath it before you print. Section 3 explains what the messages mean.
  7. Press Print label and check the print dialog — see section 9.

Check the dates every single run. The system remembers your last label, so the production date from yesterday's run is still sitting there this morning. It is the one field nothing else can catch for you.

What ends up on the label

  1. Product name, from Product name
  2. Pack size, always on its own line
  3. Production and expiry dates
  4. The barcode — the type is set per customer, section 8
  5. The number in plain figures, so a person can read it too

The customer's name, contact and address are never printed. They are held with the job so the print log can say who it was for.

03 Reading the preview Everyone

The panel on the right is a true-to-size drawing of what will come out of the printer, plus a line of measurements and a message. Read the message.

✓ Green — go ahead. The code is encoded correctly and every measurement is inside tolerance for this label stock.

△ Amber — it will probably work, but test one. Usually the bars are getting thin or the code is getting short. Print a single label and scan it before committing to a run of five hundred.

! Red — do not print this. Either the number cannot be encoded at all, or the content is taller than the label and the top and bottom are being cut off. Section 12 lists what to do about each.

The measurement line

Underneath the preview: the label size, the code type, the size of the code, the module width (the width of the thinnest bar), the printer resolution, and — for a QR — its version and error-correction level.

Module width is the number that decides whether a scanner can read your label. Below one printer dot it cannot print evenly at all; below about 0.25 mm it gets unreliable. The app watches this for you and says so.

“This barcode carries”

For a GS1-128 or a Digital Link QR, a small panel lists every field that went into the code, each with its identifier — the production date, the expiry date, the batch. Check it before a long run: it is the only place you can see that the right dates actually made it in.

04 Printing a mixed run Everyone

The queue lets you print several different products — even for different customers, on different label sizes — in one go.

  1. Set up the first label as usual and press Add to queue.
  2. Change the fields for the next one and add that too. Repeat.
  3. Adjust the number of copies on any queued line by typing straight into it.
  4. Press Print queue. Each label goes onto a page of its own correct size.
  5. Clear queue empties it when you are done.

A queued line keeps the code type it was queued with. If someone changes a customer's setup while your queue is sitting there, what you queued is still what prints.

The queue lives in this browser on this machine. It is not shared, and it does not survive clearing your browser data.

05 Products Everyone

The catalog saves you retyping a name, a pack size and a barcode number every time. Every product belongs to exactly one customer.

  1. Open Products and fill in the name, pack size, barcode number and customer.
  2. Press Add product.

You can also press Save to products on the Print tab to file whatever is currently in the form.

If you are an operator

Your new product is saved straight away but marked PENDING, with your name against it. It cannot be printed until an administrator approves it, and it will not appear in the Print tab's product list until then. You can still edit or withdraw your own proposal while it waits.

If you are an administrator

A number appears on the Products and Customers tabs showing how many are waiting. Open the tab and press Approve or Reject on each. Approving makes it printable immediately.

Import CSV brings in a whole list at once — columns name, size, code, customer. It adds new barcode numbers and updates matching ones. Export CSV takes the list out again, which is how you move a catalog between the online system and an offline station.

06 Customers Everyone

A customer holds a name and code, optional contact details, an optional logo, and — importantly — that customer's label size.

  • Name and code are all that is required. The code is what shows in brackets in the pickers, e.g. Hard Discount Philippines,Inc. (DALI).
  • The logo is only ever shown on screen, beside the customer's name, so you can see at a glance you have the right one. It is not printed on the label.
  • Label width and height give that customer its own stock. Leave them blank and the customer follows the house default.
  • A customer with products against it cannot be deleted until those products are moved or removed.

Operators can propose a new customer; it waits for approval exactly like a product does.

07 Label setup Administrators

One company at a time. Everything on this tab belongs to whichever company is chosen at the top — including which code type its labels carry.

  1. Open Label setup and use Whose labels are you setting up? to pick the company. The banner tells you whether it has its own stock or is still following the house default.
  2. Set the size preset (or type a width and height), the margin, and the printer resolution to match the stock actually loaded in that printer.
  3. Press Auto-fit to stock. This grows the text and the code to the largest size that still fits, then you can adjust by eye.
  4. Choose the code type and the measurements that go with it.

House default versus a company's own. Every company follows the house default until you change something about its stock — at that moment it gets its own copy, and the banner says so. Clear — follow house default puts it back.

Printer resolution, darkness and print speed belong to the machine, not the company. Changing those does not detach anyone from the house default.

Auto-fit after you change anything structural. Switching to a code type that needs more room — a QR, or a GS1-128 carrying dates and a batch — can push the content past the bottom of the label. The preview will turn red and say so; press Auto-fit and it will resize to fit.

08 Which code type Administrators

Set per company, on Label setup. All of them carry the same item number — what differs is how much else travels with it, and who can read it.

TypeUse it forNumber it needs
Code 128The bars on our original sample label. The default.Any number
GS1-128The same bars, carrying the production date, expiry date and batch as labelled fields. Best choice for traceability and for receiving at a distribution centre.Any number; a real GTIN if you have one
EAN-13Scanning at a supermarket checkout.12 or 13-digit GTIN
EAN-8Checkout, on packs too small for an EAN-13.8-digit GTIN-8 from GS1
UPC-ACheckout, North American trade.11 or 12-digit GTIN
ITF-14The outer carton, delivering into a distribution centre. Printed inside a heavy frame so a clipped corner fails instead of misreading.13 or 14-digit GTIN
QR CodeAnything a phone should be able to read.Any number
QR · GS1 Digital LinkA QR that a till can read as a product and a shopper's phone opens as a web page.A real GTIN

The retail types need real GTINs from GS1 Philippines. Our own eight-digit works codes are not GTINs. If you enter one, the app will tell you the check digit is wrong and print nothing — that is the app protecting you, not a fault. A barcode that is one digit out does not fail; it scans cleanly to a number belonging to another company.

EAN-8 is the trap: it is also eight digits, so our codes look like they would fit. They will not. EAN-8 numbers have to be allocated by GS1 and end in a check digit.

If you are unsure, GS1-128 is the one worth moving to: it is the same bars we already print, and it means one scan captures the dates and the batch instead of somebody reading them off the label and typing them in.

09 Getting it on paper Everyone

Two ways. Use the first unless someone has set you up for the second.

Through the printer driver — the normal way

  1. Press Print label (or Print queue).
  2. In the print dialog, choose your Zebra or Godex printer.
  3. Set the paper size to the same size as the label.
  4. Set scale to 100% — not “fit to page”, which quietly shrinks the barcode until it will not scan.
  5. Turn margins off, and turn background graphics on if your browser offers it.

The page size is already built into the label, so a correctly set-up dialog needs no adjusting between runs. Once it is right, it stays right.

Direct ZPL — sharpest bars

Sending ZPL straight to the printer's port skips the driver, and the printer renders the bars at exact dot boundaries. Use Copy ZPL or Download .zpl on the Print tab. The layout matches, but the text comes out in the printer's own built-in font rather than the typewriter face of the sample label.

10 The print log Everyone

Every run is recorded automatically. Nobody has to write anything down.

Each row holds the date and time, who printed it, the customer, the product, the pack size, the barcode number, the production and expiry dates, and how many labels.

  • Export CSV gives you the whole log for a spreadsheet — for a recall trace, a customer query, or a month-end count.
  • Only an administrator can clear the log.
  • The name on each row is whoever was signed in. This is exactly why the Lock button exists: labels printed under your name are your responsibility.

11 Accounts Administrators

The Users tab. Names here are the names that appear in the print log, so put in real ones.

  1. Fill in the person's name, their work email as the username, and a role.
  2. Set a password and repeat it. Tell them to change it when they first sign in.
  3. Press Add a user.

Most people here already have a login. Our other Meatplus systems share the same account list, so adding an email that already exists grants that person label access rather than creating a second account. Their existing password keeps working unless you type a new one.

For the same reason, removing someone here removes their label access only. It does not delete their login, because that would lock them out of every other system too.

  • A username cannot be changed once the account exists.
  • Editing someone and leaving the password boxes empty keeps their current password.
  • You cannot remove your own access.
  • Export users CSV gives names, usernames and roles only — never passwords.

12 When it looks wrong Everyone

What you seeWhat to do
“Waiting for approval” after signing in Your account has no role yet. Ask an administrator to set one on the Users tab.
The product list is empty, or your product is missing from it Check you have the right customer selected — the list is filtered by it. If it is a new product you added, it may still be PENDING approval; pending items are deliberately kept out of the Print tab.
Red: “the top and bottom are being cut off” The content is taller than the label. An administrator should open Label setup for that customer and press Auto-fit to stock.
Amber: module width is below the rule of thumb The bars are getting thin. Print one and scan it. If it fails, an administrator can widen the code, use a bigger label, or shorten what the code carries.
Red: “should end in 7, not 0” A retail code type is on, and the number is not a valid GTIN. Either enter the real GTIN, enter it without the last digit and let the check digit be worked out, or switch that customer back to Code 128.
Red: “a Digital Link has to start from a GTIN” Same cause. Use a plain QR or GS1-128 until GS1 has allocated a GTIN.
Labels print at the wrong size, or the barcode is squashed The print dialog. Paper size must match the label, scale must be 100% and not “fit to page”, margins off.
The printed barcode will not scan but the preview was green Almost always the print dialog scaling. After that, check printer darkness and that the label stock is seated properly.
Someone else's change is not showing Press Refresh in the top bar. It reloads products, customers and settings from the database.
The screen looks out of date after an update Hold Ctrl and Shift and press R to force a full reload.

Before a long run, print one and scan it. Thirty seconds here has saved entire pallets of relabelling. It is the single most useful habit on this system.
